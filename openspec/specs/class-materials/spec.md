# class-materials Specification

## Purpose
让教师把教学材料发布到本班的知识库，并让班级成员检索本班材料，同时在服务端强制以班级作为所有材料访问的数据边界。

## Requirements

### Requirement: 教师可把材料上传进知识库

系统须（SHALL）允许教师把教学材料上传到该教师所在班级的知识库。上传的材料须（SHALL）被持久化，并须（SHALL）创建一条把该材料关联到上传教师及其班级的元数据记录。上传成功后，系统须（SHALL）从文件内容中提取正文（body_text）与材料一并保存，作为知识库切分与索引的唯一输入；正文与原文件均保持上传时的原样，不做改写。

#### Scenario: 教师上传成功并入库

- **WHEN** 教师通过上传端点提交一份材料
- **THEN** 系统返回 2xx，且 materials 表存在一行 `class_id = 教师所在班`、`uploader_id = 该教师`、`stored_path` 指向已落盘文件（判定通过：响应 2xx + 库中存在该记录 + 文件在盘上）

#### Scenario: 上传后刷新列表可见

- **WHEN** 教师上传成功后刷新本班材料列表
- **THEN** 系统返回的列表包含该新上传记录（判定通过：GET /materials 响应含该记录 id）

#### Scenario: 正文随上传保存且与文件内容一致

- **WHEN** 教师上传成功后查询该材料记录
- **THEN** 记录的正文与上传文件解码后的文本一致，且后续切分、索引与摘录均以该正文为源（判定通过：body_text 与文件内容一致 + 切片字符区间落在正文范围内）

### Requirement: 学生不能上传材料

系统须（SHALL）拒绝任何来自学生账号的材料上传。该拒绝必须（MUST）由上传端点返回 HTTP 403 Forbidden，且必须（MUST）在服务端执行、不触达存储，独立于任何前端 UI 隐藏。

#### Scenario: 学生上传返回 403 且不入库

- **WHEN** 学生调用上传端点
- **THEN** 系统返回 403 Forbidden，且不落盘任何文件、不写入任何 materials 行（判定通过：响应 403 + 库与上传目录无新增）

#### Scenario: 教师上传被允许

- **WHEN** 教师调用上传端点
- **THEN** 系统返回 2xx 并存储该材料（判定通过：响应 2xx + 材料被存储）

### Requirement: 班级是服务端强制的数据边界

系统须（SHALL）按调用方所在班级过滤所有材料读取。A 班的调用方不得（MUST NOT）读取、列出或以任何方式访问属于 B 班的材料。此过滤必须（MUST）对每个请求在服务端执行，不论客户端行为如何，且不得（MUST NOT）依赖隐藏 UI 控件。

#### Scenario: 同班访问被允许

- **WHEN** A 班成员请求本班材料
- **THEN** 系统返回的材料记录全部属于 A 班（判定通过：返回记录的 class_id 均为 A 班）

#### Scenario: 跨班访问被拒

- **WHEN** A 班成员试图访问 B 班材料（通过列表、直接按 id 或任何端点）
- **THEN** 系统返回 404 且响应不含任何 B 班材料记录；跨班访问与"材料 id 不存在"返回完全同形的 404，不泄露资源是否存在（判定通过：跨班 id 与不存在 id 均得 404 + 两者响应体一致 + 响应体无 class_id = 他班的记录）

#### Scenario: 边界在服务端强制

- **WHEN** A 班调用方提交针对 B 班材料的请求（含在 query、Header 或表单中携带他班 class_id），即使无前端控件隐藏
- **THEN** 服务端拒绝返回该 B 班材料，且租户标识只取自服务端会话、客户端传入一律忽略（判定通过：响应不含 B 班材料内容 + 携带 class_id 参数不改变结果）

### Requirement: 班级材料列表只含本班记录

系统须（SHALL）提供查询调用方所在班级材料的方式。该列表须（SHALL）只返回属于该班级的材料，包括上传后新增的记录。

#### Scenario: 列表只含本班记录且含新上传

- **WHEN** 班级成员在教师完成一次上传后列出本班材料
- **THEN** 列表包含该新上传记录，且不包含任何其他班级的记录（判定通过：列表记录的 class_id 全为本班 + 含新记录 id）

### Requirement: 上传内容通过白名单校验且失败不留残留

系统须（SHALL）仅接受扩展名为 `.txt` / `.md` 的非空 UTF-8 文本材料，文件大小不得（MUST NOT）超过环境变量配置的上限（`MAX_UPLOAD_BYTES`）。存储文件名必须（MUST）由服务端生成，客户端提供的文件名仅用于展示标题，不得（MUST NOT）参与存储路径构造。校验或入库的任何一步失败时，系统不得（MUST NOT）在上传目录留下文件，也不得（MUST NOT）写入 materials 记录。

#### Scenario: 非法扩展名被拒绝且无残留

- **WHEN** 教师上传扩展名为 `.exe`（或任何非 `.txt`/`.md`）的文件
- **THEN** 系统返回 4xx 且不保存文件、不写入 materials 行（判定通过：响应 4xx + 上传目录无新增文件 + materials 行数不变）

#### Scenario: 超限文件被拒绝且无残留

- **WHEN** 教师上传超过 `MAX_UPLOAD_BYTES` 的文件
- **THEN** 系统返回 413 且不保存文件、不写入 materials 行（判定通过：响应 413 + 上传目录无新增文件 + materials 行数不变）

#### Scenario: 入库失败不残留孤儿文件

- **WHEN** 文件已通过校验并落盘，但数据库写入失败
- **THEN** 系统删除已落盘文件，且不存在指向缺失文件的 materials 记录（判定通过：磁盘与 materials 表均无该次上传痕迹）

### Requirement: 材料详情与文件下载须经鉴权接口

系统须（SHALL）通过要求登录并校验班级的接口提供材料详情与文件下载。上传目录不得（MUST NOT）作为无需鉴权的静态目录对外暴露。详情响应不得（MUST NOT）包含服务端磁盘绝对路径。

#### Scenario: 本班成员经鉴权接口获取详情与文件

- **WHEN** 材料所属班级的已登录成员请求该材料的详情或下载
- **THEN** 系统返回 200 与材料元数据或文件内容，且不返回服务端磁盘绝对路径（判定通过：响应 200 + 含材料元数据或文件内容 + 响应体不含 stored_path 绝对路径）

#### Scenario: 直接猜测上传目录路径取不到文件

- **WHEN** 调用方不经鉴权接口、直接请求上传目录中的文件路径
- **THEN** 系统不提供该文件内容（判定通过：该请求不返回 200 文件内容）
