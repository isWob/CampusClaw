## Requirements

### Requirement: 班级范围检索仅对已登录成员开放且班级取自会话

系统须（SHALL）向已登录的本班成员（教师与学生）提供知识库检索，且须（SHALL）仅以服务端会话中的班级标识限定检索范围。请求的查询串、JSON 正文或请求头中携带的任何班级编号必须（MUST）被解析后丢弃。未登录调用必须（MUST）返回 401。

#### Scenario: 未登录检索被拒

- **WHEN** 未携带有效会话调用检索端点
- **THEN** 系统返回 401，响应不含任何切片正文或材料标题（判定通过：响应 401 + 响应体无材料内容）

#### Scenario: 请求携带他班 class_id 被丢弃

- **WHEN** A 班会话在请求体中写入 B 班的 class_id 后发起检索
- **THEN** 系统仍以 A 班为过滤条件，响应中不出现任何 B 班切片（判定通过：携带与不携带 class_id 两次响应完全一致 + 无 B 班内容）

### Requirement: 跨班级检索对外表现为无命中

使用仅存在于其他班级正文中的词发起检索时，系统必须（MUST）返回 200、空的命中列表与「资料中未找到相关内容」文案，不得（MUST NOT）以 403 或 404 区分「属于他班」与「不存在」，也不得（MUST NOT）返回他班切片。

#### Scenario: 他班独有词表现为无命中

- **WHEN** A 班会话以仅出现在 B 班材料正文中的关键词检索
- **THEN** 系统返回 200、hits 为空且附「资料中未找到相关内容」（判定通过：200 + 空 hits + 响应无 B 班内容）

### Requirement: 上传成功后自动建立切片索引

材料上传成功后，系统须（SHALL）提取正文并按策略切分为切片，逐片完成向量嵌入并写入向量库；切片正文、序号与字符区间须（SHALL）持久化在关系库，向量库中仅保存向量与标识，向量主键须（MUST）等于切片主键。嵌入失败时材料记录必须（MUST）保留、对应切片标记为失败，且不得（MUST NOT）向向量库写入不完整数据。

#### Scenario: 教师上传后切片与向量就绪

- **WHEN** 教师上传一份 .txt/.md 材料且嵌入成功
- **THEN** 关系库出现该材料的若干切片（含序号与字符区间），向量库中每片有一条向量记录且主键与切片主键一致、payload 不含正文（判定通过：切片数与向量数一致 + 主键一一对应 + payload 无正文）

#### Scenario: 嵌入失败材料保留且无残缺向量

- **WHEN** 某切片嵌入调用失败
- **THEN** 材料记录与其切片仍在关系库、切片标记为失败，向量库中无该切片的向量（判定通过：材料仍可下载 + 切片嵌入状态为失败 + 向量库无该主键）

#### Scenario: 原文与正文不被改写

- **WHEN** 切分应用了预处理（如移除链接、折叠空白）
- **THEN** 材料原文件与关系库保存的正文仍为上传原样，切片字符区间对应预处理后的文本（判定通过：原文件字节不变 + 正文与原文件内容一致）

### Requirement: 三种切分策略且教师可重建索引

系统须（SHALL）支持 `auto`（默认：最大 800 字、重叠 80 字、优先在空行/换行/句号断开）、`custom`（长度 100–2000 字、重叠 0%–50%、无断点按最大长度强制截断、可选预处理）与 `hierarchy`（按 Markdown #/##/### 分章、标题留在章内、过长章再按 auto 切分）三种切分策略。教师须（SHALL）能够对已入库材料按指定策略重建索引：先删除旧切片与旧向量记录，再按本次策略重新写入。已入库材料不得（MUST NOT）随策略变化自动重新切分。

#### Scenario: 默认策略切分并入库

- **WHEN** 教师上传材料且未指定策略
- **THEN** 系统按自动窗口（≤800 字、重叠 80 字）切分，且任一切片不超过 800 字（判定通过：切片均 ≤800 字 + 相邻切片存在重叠）

#### Scenario: 重建索引替换旧切片与旧向量

- **WHEN** 教师对已入库材料以与上传时不同的策略请求重建索引
- **THEN** 旧切片与旧向量记录被删除，新切片按本次请求的策略生成（判定通过：切片集合被替换 + 切片数与新策略一致 + 向量库无旧主键残留）

#### Scenario: custom 参数越界被拒

- **WHEN** 教师以长度 <100 或 >2000 字、或重叠比例超出 0%–50% 的参数请求切分或重建
- **THEN** 系统返回 4xx 且不改动既有切片与向量（判定通过：4xx + 切片集合不变）

### Requirement: 关键字检索仅查询全文索引

系统须（SHALL）提供关键字检索：仅查询关系库全文索引并按全文相关度排序，不调用嵌入服务、不访问向量库。中文检索须（SHALL）支持 ≥2 字词的命中（按 2-gram 预切分索引）。仅已完成索引的切片可被命中。

#### Scenario: 原词命中且不触发嵌入

- **WHEN** 以正文原词发起 keyword 检索
- **THEN** 命中包含该词所在切片且排序按全文相关度，全过程不调用嵌入端点、不访问向量库（判定通过：命中含该切片 + 嵌入服务与向量库无调用记录）

### Requirement: 向量检索按会话班级过滤并回表取正文

系统须（SHALL）提供向量检索：问句经服务端嵌入为向量后，在向量库中按会话班级过滤并按余弦相似度排序，余弦相似度低于 0.35 的候选必须（MUST）被丢弃；命中后必须（MUST）以向量主键回关系库取回切片正文，且回表时再次核对班级。

#### Scenario: 同义改写命中语义相近切片

- **WHEN** 以与正文表述不同但语义相近的问句发起 vector 检索
- **THEN** 命中包含语义相近切片，摘录取自关系库切片正文且相似度不低于 0.35（判定通过：命中非原词切片 + 摘录与关系库切片正文一致）

#### Scenario: 低相似度候选被丢弃

- **WHEN** 问句与本班所有切片语义均无关
- **THEN** 系统返回 200、hits 为空与「资料中未找到相关内容」，不以低分候选凑数（判定通过：200 + 空 hits）

### Requirement: 混合检索以 RRF 融合且为默认模式

系统须（SHALL）提供混合检索并作为默认模式：同时执行关键字与向量两条路径，各自按绝对分数过滤后按名次以 RRF（k=60）融合排序；缺席的一路不得（MUST NOT）贡献分数。混合模式不得（MUST NOT）将两路分数直接相加。

#### Scenario: 两路均命中的切片排前

- **WHEN** 问句既有原词命中又有语义命中
- **THEN** 两路均命中的切片在最终排序中高于仅单路命中的切片（判定通过：双命中切片名次靠前）

#### Scenario: 向量路缺席时关键字路独立有效

- **WHEN** 向量路径无候选时发起 hybrid 检索
- **THEN** 结果由关键字路名次单独决定且可返回命中（判定通过：返回关键字路切片 + 排序与单路名次一致）

### Requirement: 每条命中可溯源至原文

检索命中的每条结果须（SHALL）包含材料标识与标题、切片序号、字符区间与摘录，并提供打开对应材料（详情/下载）的入口。摘录必须（MUST）取自关系库中的切片正文；响应不得（MUST NOT）包含服务端磁盘路径或向量分量。

#### Scenario: 命中字段齐全且可回溯

- **WHEN** 检索返回任一命中
- **THEN** 该命中含材料标识、材料标题、切片序号、字符区间与摘录，且以该材料标识调用详情端点可得同班 200（判定通过：字段齐全 + 摘录与关系库切片正文一致 + 详情可打开）

#### Scenario: 响应不含敏感信息

- **WHEN** 检索返回结果
- **THEN** 响应不含服务端磁盘绝对路径，也不含任何向量分量（判定通过：响应体无路径与向量数据）

### Requirement: 空查询与组件降级语义

空查询必须（MUST）返回 400。向量库或嵌入能力不可用时，关键字检索必须（MUST）仍可返回结果，向量与混合检索必须（MUST）返回 503 且不得（MUST NOT）编造相似度分数。

#### Scenario: 空查询 400

- **WHEN** 以空字符串或不携带 query 调用检索端点
- **THEN** 系统返回 400（判定通过：400）

#### Scenario: 向量库不可用时降级

- **WHEN** 向量库停止服务后分别以 keyword 与 vector/hybrid 检索
- **THEN** keyword 仍返回正确命中，vector 与 hybrid 返回 503 且响应无相似度分数（判定通过：keyword 200 有命中 + vector/hybrid 503 + 无分数字段）

### Requirement: 先检索后生成的问答与引用标注

系统须（SHALL）提供问答端点：先以会话班级执行混合检索取前 4 条切片，仅当存在命中切片时才调用对话网关，输入仅为材料标题、切片序号、切片正文、用户最新提问与此前若干轮对话；回答中的 [n] 标注与响应 citations 列表顺序须（SHALL）一致。无命中时必须（MUST）直接返回「资料中未找到相关内容」与空 citations，不调用对话网关。客户端注入的 system 消息必须（MUST）被丢弃，系统提示词由服务端组装。本端点不得（MUST NOT）返回向量分量、他班切片或流式输出。

#### Scenario: 有依据时回答带一致引用

- **WHEN** 以材料中确有依据的问题调用问答端点
- **THEN** 响应返回简短回答与 citations，回答中 [1]、[2] 标注与 citations 顺序一致（判定通过：标注序号与 citations 一一对应 + citations 均为本班切片溯源字段）

#### Scenario: 无依据时不调用生成模型

- **WHEN** 以本班材料不可能出现依据的问题（如天气、比分）调用问答端点
- **THEN** 系统返回 200、正文为「资料中未找到相关内容」、citations 为空，且对话网关无调用（判定通过：固定文案 + 空 citations + 网关无调用记录）

#### Scenario: 客户端 system 消息被丢弃

- **WHEN** 请求体中携带客户端构造的 system 消息调用问答端点
- **THEN** 该消息不进入对话网关输入，服务端仍以自己的系统提示词组装请求（判定通过：网关输入不含客户端 system 内容）

### Requirement: 向量库与模型网关不对客户端暴露

向量库必须（MUST NOT）映射宿主端口或提供任何客户端可达入口；嵌入与对话网关的密钥必须（MUST）仅存放于服务端环境变量；浏览器只允许调用本站检索/问答接口。页面不得（MUST NOT）展示向量分量。

#### Scenario: 客户端无法直连向量库

- **WHEN** 从宿主机尝试访问向量库端口
- **THEN** 连接不可达（判定通过：Compose 配置中向量库服务无宿主端口映射 + 宿主访问失败）

#### Scenario: 密钥不下发页面

- **WHEN** 审查任一页面响应与静态资源
- **THEN** 不出现嵌入/对话网关密钥或向量数据（判定通过：页面源码无密钥值）
