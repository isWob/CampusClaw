## Why

校园教学平台目前没有身份认证、没有角色边界、也没有按班级隔离的数据边界。结果是任意访客都能进入受保护页面、任意账号都能上传材料、A 班学生能读到 B 班的材料。本次变更为平台引入登录 + 角色访问控制 + 按班级的数据边界，让教师可以安全地把教学材料发布到本班的知识库，学生只能看到自己所在班级的内容。

## What Changes

- 为教师和学生增加用户名/密码登录；对受保护页面的未认证请求由服务端重定向到登录页（而非仅在前端隐藏入口）。
- 引入教师/学生角色；材料上传接口拒绝学生调用（返回 403）。
- 把班级作为数据边界：跨班级访问材料一律由服务端拒绝，不论客户端如何请求。
- 教师可把教学材料上传进知识库；本班材料列表必须包含该上传记录。
- 提供幂等预置（种子）数据：至少两个班级，每班各一名教师 + 学生账号，便于开箱演示登录与跨班隔离。
- **安全**：密码仅以哈希形式存储（禁止明文）；签名密钥/密钥只放在服务端环境变量中。
- **运维**：提供基于 Docker Compose 的启动方式，以及 `GET /health` 健康检查端点。

## Capabilities

### New Capabilities

- `user-auth`：账号/密码登录、登出、会话、重定向到登录页的访问闸门、教师/学生角色身份、密码哈希、密钥存放于环境变量。
- `class-materials`：仅教师可用的材料上传到知识库（学生上传返回 403）、按班级范围的材料列表、服务端强制的班级边界访问控制。
- `service-health`：`GET /health` 健康检查端点、Docker Compose 启动、幂等预置（种子）数据。

## Impact

- **新增代码**：全新后端服务（仓库中暂无源码）。新增端点：登录/登出、材料上传、班级材料列表、`GET /health`。
- **新增依赖**：Web 框架（Flask）、会话处理、密码哈希（Werkzeug）、SQLite 与材料文件存储。
- **部署**：一个 `docker-compose.yml` 与服务镜像；密钥通过环境变量提供（绝不打包进镜像）。
- **数据模型**：班级、用户（角色 + 班级归属）、材料（关联上传者 + 班级），外加预置种子数据。
- 不修改任何现有 API、spec 或代码。

## Non-Goals

本课程本次变更**不做**以下内容（不在范围内）：

- 检索与问答：不对材料做全文检索、语义搜索或基于材料的问答。
- 对话助手：不提供聊天/对话式 AI 助手。
- 作业提交与批改：不支持学生提交作业、教师批改与评分。
- SSO 与生产级高可用：不接 SSO/OAuth、不做多副本负载均衡、生产级 HA 与监控告警。
- 更细权限模型：不做超出 教师/学生 + 班级归属 的细粒度授权。
- 材料高级功能：不做版本管理、在线编辑、预览渲染、转码与去重。
- 多因子认证与无密码登录：不做 MFA、魔法链接、生物识别等。
